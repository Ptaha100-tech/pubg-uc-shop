# Магазин UC для PUBG Mobile: Telegram-бот + Mini App

Покупатель открывает Mini App в боте, выбирает пакет UC, вводит Player ID и платит через ЮKassa (карта / СБП).
После оплаты заказ приходит админу в Telegram с кнопками **«Выдано»** и **«Возврат»**. Клиент получает уведомления на каждом шаге.

## Как это устроено

```
Telegram ─▶ Mini App (web/)  ──▶ FastAPI (app/) ──▶ PostgreSQL
              │                     │   ▲
              │ openLink            │   └── вебхук ЮKassa + фоновая сверка (раз в минуту)
              ▼                     ▼
        страница оплаты ЮKassa    бот (aiogram, webhook) ─▶ админу: заказ + кнопки
```

- **Безопасность Mini App:** каждый запрос подписан Telegram (`initData`), сервер проверяет HMAC; чужой user id подделать нельзя.
- **Оплата:** статус платежа всегда перепроверяется запросом к API ЮKassa, поэтому поддельный вебхук ничего не даст. Сумма платежа сверяется с заказом.
- **Нет двойной выдачи и двойного возврата:** переходы статусов атомарные, возврат идёт с идемпотентным ключом.
- **Потерянные вебхуки:** фоновая сверка раз в минуту добирает оплаченные заказы. Неоплаченные закрываются через `ORDER_TTL_MINUTES`.
- **Цены на момент заказа** сохраняются в заказе, смена цены не ломает старые заказы и статистику.

Статусы заказа: `pending → paid → delivered`, а также `canceled` и `refunded`.

## Запуск на сервере

Нужны VPS с Docker и домен, направленный A-записью на IP сервера (порты 80 и 443 открыты).

1. **Бот.** В [@BotFather](https://t.me/BotFather) создайте бота (`/newbot`), сохраните токен и username.
2. **ЮKassa.** В личном кабинете возьмите `shopId` и секретный ключ (Интеграция → Ключи API).
   Там же: **Интеграция → HTTP-уведомления** → URL `https://ВАШ_ДОМЕН/webhooks/yookassa`, события `payment.succeeded` и `payment.canceled`.
3. **Настройки.**
   ```bash
   cp .env.example .env
   nano .env        # заполните все значения
   ```
   Свой Telegram ID узнайте у [@userinfobot](https://t.me/userinfobot) и впишите в `ADMIN_IDS`.
4. **Старт.**
   ```bash
   docker compose up -d --build
   docker compose logs -f app     # должно появиться "started, webhook=..."
   ```
   Caddy сам получит HTTPS-сертификат. Вебхук бота и кнопка меню регистрируются автоматически.
5. **Цены.** Напишите боту `/admin`. Пакеты 60 / 325 / 660 / 1800 / 3850 / 8100 UC создаются **выключенными с нулевой ценой**, чтобы случайно ничего не продать:
   ```
   /price 325 299      цена продажи, ₽
   /cost 325 270       ваша закупка, ₽ (для расчёта прибыли)
   /toggle 325         включить пакет в магазине
   ```
6. **Тестовый заказ** на 1 пакет с вашей картой, затем возврат кнопкой. Так вы проверите весь цикл.

## Деплой через GitHub

GitHub хранит код и по `git push` сам обновляет бота на вашем сервере (workflow `.github/workflows/deploy.yml`: сначала тесты, потом деплой). Сам GitHub бота не запускает, для этого нужен VPS.

1. **Репозиторий.** Создайте на github.com **приватный** репозиторий (без README) и отправьте код:
   ```bash
   cd pubg-uc-shop
   git init -b main
   git add .
   git commit -m "Initial commit"
   git remote add origin git@github.com:ВАШ_ЛОГИН/pubg-uc-shop.git
   git push -u origin main
   ```
   Файл `.env` в `.gitignore`: токены и ключи в репозиторий не попадут. Никогда не коммитьте его.
2. **Сервер (один раз).** Установите Docker и склонируйте репозиторий:
   ```bash
   git clone git@github.com:ВАШ_ЛОГИН/pubg-uc-shop.git /opt/pubg-uc-shop
   cd /opt/pubg-uc-shop && cp .env.example .env && nano .env
   docker compose up -d --build
   ```
   Для приватного репозитория добавьте на сервере SSH-ключ как **Deploy key** (GitHub → Settings → Deploy keys, только чтение).
3. **Ключ для автодеплоя.** На своём компьютере создайте отдельный ключ: `ssh-keygen -t ed25519 -f deploy_key -N ""`.
   Публичную часть (`deploy_key.pub`) добавьте на сервер в `~/.ssh/authorized_keys`.
4. **Секреты GitHub** (репозиторий → Settings → Secrets and variables → Actions):
   `SSH_HOST` — IP или домен сервера, `SSH_USER` — пользователь (например, `root`), `SSH_KEY` — содержимое файла `deploy_key` (приватный ключ).

После этого каждый `git push` в ветку `main` тестирует и выкатывает новую версию. Статус виден во вкладке Actions.

## Команды админа

| Команда | Что делает |
|---|---|
| `/stats` | заказы, выручка, прибыль: сегодня / 7 / 30 дней / всё время |
| `/pending` | оплаченные, но не выданные заказы |
| `/order ABC12345` | найти заказ по номеру |
| `/products` | список пакетов, цены, маржа |
| `/price`, `/cost`, `/toggle` | управление пакетами |
| `/addpack 2460 1990 1850` | новый пакет (UC, цена, закупка) |
| `/ban id`, `/unban id` | блокировка покупателя |

## Подключение поставщика (автовыдача)

Сейчас `SUPPLIER=manual`: вы пополняете UC сами и жмёте «Выдано». Когда выберете поставщика с API:

1. Создайте `app/suppliers/<имя>.py` с классом-наследником `Supplier` и методом `deliver(order, user)`.
   Он вызывает API поставщика и возвращает `DeliveryResult("delivered" | "queued" | "failed")`.
2. Добавьте его в словарь `registry` в `app/suppliers/__init__.py`.
3. Поставьте `SUPPLIER=<имя>` в `.env` и перезапустите: `docker compose up -d`.

Остальной код (оплата, уведомления, возвраты) менять не нужно. Если автовыдача вернула `failed`, заказ остаётся «оплачен» и вам приходит алерт с кнопками.

## Эксплуатация

- **Бэкап базы:** `docker compose exec db pg_dump -U shop shop > backup_$(date +%F).sql` (настройте по cron).
- **Обновление:** `git pull && docker compose up -d --build`.
- **Логи:** `docker compose logs -f app`.
- **Схема БД** создаётся автоматически при старте. Если позже понадобятся изменения таблиц, подключите Alembic.
- **Тесты:** `pip install pytest && pytest tests`.

## Что нужно проверить до запуска

Я не мог запустить проект целиком в этой среде (нет доступа к Telegram, ЮKassa и установке пакетов). Проверены только модули с чистой логикой (17 тестов) и синтаксис всего кода. Первый запуск и тестовую оплату сделайте обязательно, прежде чем принимать деньги.

**Риски, которые техника не закрывает:**

- **Правила Telegram.** Условия Telegram Stars описывают Stars как способ платить за цифровые товары в ботах и Mini App. Запрета других способов в них нет, но и разрешения явно нет. Есть риск, что к боту применят санкции за приём оплаты вне Stars. Оплата изолирована в `app/yookassa.py` и `app/orders.py`, добавить Stars можно без переписывания остального.
- **Правила игры.** Перепродажа UC зависит от условий Krafton/Tencent и поставщика. Покупайте только у легального поставщика: UC с краденых карт приводят к чарджбэкам и блокировке аккаунтов ваших клиентов.
- **Чеки и налоги.** Если принимаете платежи как ИП или самозанятый, включите чеки (`RECEIPT_ENABLED=true`) и согласуйте `RECEIPT_*` с бухгалтером. Это зависит от вашего статуса и настроек кассы в ЮKassa.
